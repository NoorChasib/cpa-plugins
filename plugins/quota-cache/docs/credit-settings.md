# Credit settings

From 0.2.0, Quota Cache keeps everything you enter about Claude API credits and Claude subscriptions: the Claude Console organizations, each organization's monthly credit, refill date and Console readings, and each Claude subscription's renewal date. You enter them on Quota Cache's page in CPA's sidebar. Quota Cache prices each organization's metered tokens at Anthropic's list prices and publishes the result beside its snapshot, in the [credit state file](cache-format.md#credit-state-file), so Quota Glance shows the same figures and Reset Priority routes on them. Quota Glance 0.8.0 shows them read-only, with a link to this page.

This page covers the editor, the save route, the import from Quota Glance, what happens when a file cannot be read, and rollback. The files themselves are described in [the cache format](cache-format.md#operator-data-beside-the-snapshot).

## The page

Open **Quota Cache** in CPA's sidebar while signed in to CPA's console on the same address, with **Remember password** ticked. None of these values is in Quota Cache's **Edit config** on CPA's Plugins page (the **Configure quota-cache** dialog), whose **Config fields** hold only where the cache lives, how it polls and the OpenRouter key. The page uses the console's remembered management key; without one it says so and sends nothing. It saves only when you press a button, and after CPA refuses the key (401 or 403) it never sends that key again until you select **Refresh view**, because CPA locks an address out of its management API for 30 minutes after five failed attempts. While a card is open, **Refresh view** is off, so a refused save is handled on the card: for a key CPA itself refused, and during a lockout, **Save** stays off until the console holds another key or the lockout ends; after any other refusal, such as one from a proxy in front of CPA or a lockout that has ended, **Save** stays on and pressing it is the one try. Your changes are kept either way until you reload. A phone, a bookmark or Quota Glance's menu bar can read the figures in Quota Glance but cannot edit them.

The page has three cards under the status:

- **Organizations**: one row per Claude Console organization, with its label and a shortened Organization ID. While the list is empty, **Add organization** takes a label and the **Organization ID** from Console under **Settings > Organization**, in any case and with spaces trimmed. **Edit organizations** renames or removes them, and its **Add an organization** row adds one. While the organizations file cannot be read, the card lists the configuration's organizations, read-only.
- **Claude API credits**: one row per organization, with its monthly credit, refill date, Console reading, what was used and what is left. **Set credits and dates**, or **Edit credits and dates** once a credit is set, sets the **Monthly credit, USD** (1 to 7 digits, up to 2 decimals, `0` allowed), **Refills on, UTC** (a date from 2000 to 2099) and a **Console reading** (the amount Console shows and when you read it, from 48 hours ago to 5 minutes ahead). Each value shows where it comes from: entered here, or from the configuration, with **Use config** to go back to the configuration's value.
- **Claude renewal dates**: one row per Claude credential on CPA's roster, disabled ones included, with the renewal in effect and where it comes from. **Set renewal dates** enters the day a subscription renews, which Anthropic does not report; **Use estimate** goes back to the estimate from when the subscription began. A date saved for a credential CPA no longer lists is shown by a shortened auth index and can be removed.

A value entered here wins over the configured one. The configured values are an organization's `monthly-usd` and `renews` from `claude-api-credits`, which moved to the organizations file with it (below). A reading taken on a refill day, a reading above the monthly credit, and one too old to use are flagged on the row.

### Organizations

- An organization's ID never changes: a different ID is a different organization, since its account is a hash of the ID. To change one, remove it and add the new one.
- Removing an organization keeps the amounts and readings entered for it in the settings file, listed under the API credit card as an orphan you can clear, the last organization's too. Adding the same Organization ID again brings them back.
- A moved organization's configured monthly credit and refill date (its `monthly-usd` and `renews`) belong to its entry and go with it: adding it again does not bring them back, so enter them on the page. There is no reorder; removing and adding an organization again puts it last.
- An organization is counted from the first request after it is added, with no restart. Removing the last one stops the meter, which records the stop; adding one starts it again from its file, with the gap.
- At most 16 organizations, and labels are unique ignoring case.
- A save is checked against the list its renames and removals were made on, even when the view updated while the card was open. If another device changed the organizations since, nothing is saved: the card shows the current list, names the renames and removals it dropped, and keeps a filled-in **Add an organization** row.

**The move from the configuration.** Quota Cache 0.1.13 and 0.1.14 read the organizations from `claude-api-credits`. The first time 0.2.0 runs with that list and no organizations file, it moves every item with no problem into the file, in order, each with its valid `monthly-usd` and `renews` as its configured values, and logs `quota-cache moved its Claude Console organizations to its page` with how many moved and how many were skipped. An item with a problem (a missing label, an invalid or repeated Organization ID) is skipped, since the file holds only what its rules accept. After the move:

- The page is the only place to edit organizations. The configuration's list is ignored, the page says so in a note you can dismiss, and CPA's log says so once per load: `quota-cache keeps Claude Console organizations on its page; claude-api-credits in its configuration is ignored`. You can leave the list; only an older Quota Cache reads it. Nothing on the page is written back to it, so it stays as it was at the move until you change it. Before a rollback it has to match the page again, with each organization's configured `monthly-usd` and `renews`, which the page takes from the organizations file since the move; a list deleted meanwhile is written again from the page ([rollback](#rollback)).
- To bring in an item the move skipped, add it on the page.
- To start over from the configuration, delete `snapshot.organizations.json`. Within a few seconds Quota Cache moves the configuration's list again, at a revision no earlier file had, so a save from a page that read the deleted file meets the moved list as a conflict. This discards every organization change made on the page since the move: an organization added there leaves the list, and its saved values become orphans until it is added again; renames go back to the configuration's labels; and organizations removed there come back. Nothing else moves the list again.
- If every item had a problem, nothing is written and the items stay in force from the configuration, with their problems shown, as in 0.1.x.

## The save route

The page saves through one management route, `POST /v0/management/plugins/quota-cache/settings`. CPA checks the management key, which it takes only from a header, before Quota Cache sees the request. There is no route on the public resource tree. Every answer is JSON with `Cache-Control: no-store`, and a saved change is published to the credit state file before the answer.

The checks run in this order, and the first that fails answers:

| # | Check | Answer |
| --- | --- | --- |
| 1 | The cache is not running, including `enabled: false` | `503 {"error":"cache_stopped"}` |
| 2 | `Sec-Fetch-Site` is sent and is not `same-origin` (a request with none, from curl or a script, passes) | `403 {"error":"cross_site"}` |
| 3 | The body is not `application/json` | `415 {"error":"unsupported_media_type"}` |
| 4 | The body is over 4096 bytes | `400 {"error":"invalid_request"}` |
| 5 | An organizations batch while the organizations file cannot be read | `503 {"error":"organizations_unavailable"}` |
| 5 | Any other request while the settings file, or Quota Glance's `settings.json` that blocks the first import, cannot be read, or while the import record is there but cannot be opened or read | `503 {"error":"settings_unavailable"}` |
| 6 | The request's own rules, below | |

The request's `kind` picks one of four bodies. Each row of a batch carries the `baseRevision` the page read, `""` for a row with nothing saved.

- **`apiCredits`**: `{"kind":"apiCredits","items":[{"id":"org-1a2b3c4d5e6f","baseRevision":"12","monthlyUsd":"200"|null,"renews":"2026-10-29"|null,"reading":{"remainingUsd":"143.20","at":"2026-10-12T09:20:00Z"}|null}]}`, 1 to 16 rows. Every key is required; `null` means not set here.
- **`renewals`**: `{"kind":"renewals","items":[{"id":"<16 hex auth index>","baseRevision":"3","date":"2026-09-10"|null}]}`, 1 to 32 rows.
- **`importLegacy`**: `{"kind":"importLegacy","baseRevision":"<the settings file's revision, \"\" without one>"}`. It never names a file.
- **`organizations`**: `{"kind":"organizations","baseRevision":"<the organizations file's revision, \"\" without one>","ops":[…]}`, 1 to 16 operations, applied in order and committed whole or not at all: `{"op":"add","label":"team","organizationId":"<uuid>"}`, `{"op":"rename","id":"org-1a2b3c4d5e6f","label":"team-two"}` and `{"op":"remove","id":"org-1a2b3c4d5e6f"}`.

The answers after the checks:

| Answer | When |
| --- | --- |
| `200 {"ok":true,"unchanged":false,"revision":"13","settings":{"<id>":<block>}}` | A saved batch. Each block is the row as now published: an account's `settings` block, a credential's `{date, revision, updatedAtEpoch}`, or `null` for a cleared orphan or a cleared date |
| `200 {"ok":true,"unchanged":true,"revision":"12"}` | A batch whose rows already hold what was sent; nothing is written |
| `200 {"ok":true,"unchanged":false,"revision":"13","counts":{…}}` | An import, with what it imported |
| `200 {"ok":true,"unchanged":bool,"revision":"5","organizations":[{"id","label","organization_id","has_default_monthly_usd","has_default_renews"}]}` | An organizations batch, with the list now in the file |
| `400 {"error":"invalid_request"}` | Anything that is not exactly one of the bodies above |
| `400 {"error":<code>,"id","field"}` | A value the rules refuse: `invalid_monthly_usd`, `invalid_renews`, `invalid_date`, `invalid_reading_amount`, `invalid_reading_time` (outside 48 hours back to 5 minutes ahead) or `reading_before_refill` |
| `400 {"error":<code>,"op","field"}` | An organizations operation the rules refuse, `op` being its index: `invalid_label`, `duplicate_label`, `invalid_organization_id`, `duplicate_organization`, `too_many_organizations` or `unknown_id` |
| `409 {"error":"not_editable","id","ids"}` | A row the published state does not offer: an account whose `settings.editable` is false, or a credential whose index cannot key a date. A stored row for an organization or credential no longer listed (an orphan) may only be cleared |
| `409 {"error":"not_editable"}` | An import with no Quota Glance `settings.json` that can be read |
| `409 {"error":"conflict","revision","conflicts":[ids],"current":{"<id>":<block>}}` | A batch row saved elsewhere since the page read it, with what it holds now. Sending what is already saved is not a conflict |
| `409 {"error":"conflict","revision"}` | An import whose `baseRevision` is not the settings file's |
| `409 {"error":"conflict","revision","organizations":[…]}` | An organizations batch whose `baseRevision` is not the file's, with the list now in it |
| `409 {"error":"settings_full"}` | The settings file would pass a bound even after dropping the oldest renewal dates of credentials CPA no longer lists, or the write needs a revision past 18446744073709551615, the highest there is, which only a file edited by hand holds |
| `429 {"error":"too_many_writes"}`, `Retry-After: 60` | More than 30 committed saves in a minute. The settings file and the organizations file each have their own limit; an import counts toward the settings file's |
| `503 {"error":"organizations_unavailable"}` | An `apiCredits` row for an organization the configuration does not list, while the organizations file cannot be read: it may belong to an organization in the file, so it is neither set nor cleared until the file can be read |
| `503 {"error":"settings_unwritable"}` | The file could not be written; nothing changed |

While CPA offers a schema below 6, it HTML-escapes every string in management JSON responses (`'` arrives as `&#39;`). Quota Cache registers the schema CPA offers, at most 6, which every supported CPA offers, and its status says `strings_escaped` so the page decodes the entities only when CPA escaped them.

## Importing Quota Glance's settings

Quota Glance 0.7 and older kept these values in its own `settings.json`, in exactly the settings file's format. Quota Cache imports them, and never creates, writes, renames or deletes Quota Glance's file.

**Which file.** Quota Cache looks for Quota Glance's file in three places, in this order (`client.LegacySettingsCandidates`):

1. the drop-in, `quota-glance-settings.json` in Quota Cache's data directory, which you place for a Quota Glance `data-dir` that is not the default. Placing it is deliberate, so it wins over everything else;
2. once an import has happened, the file the import record names, whether or not it is still there, so the source never switches silently;
3. otherwise `quota-glance/settings.json` beside Quota Cache's data directory (`/CLIProxyAPI/plugins/data/quota-glance/settings.json` in the documented layout), then `plugins/data/quota-glance/settings.json` against CPA's working directory.

**How it is imported.**

- **Automatic**, the first time only: while there is neither a settings file nor an import record, at a configure or within 10 seconds, a Quota Glance file that can be read is copied byte for byte as the settings file, then an `automatic` record is written. Every revision, timestamp and reading survives as it was. With no Quota Glance file, nothing is written, and the first save creates the settings file. Losing both files later looks the same as the first time, so the automatic import also refills a store after a `cache-path` move or redeploy that left them behind, and after an unreadable settings file with no record is moved aside. Quota Glance 0.8.0 no longer writes its file, so a value saved on the page before then is not among what comes back, and the note after the import says to enter any such value again.
- **Matched**: when the two files are byte for byte the same and no record says the one is a copy of the other, a `matched` record is written. That completes an import a crash cut short between its two writes, and picks follow mode up again after a rollback copied Quota Cache's settings file over Quota Glance's, also straight after **Import Quota Glance's settings**, whose own record says its file has newer revisions than Quota Glance's. A record that is there but cannot be opened or read is left as it is until it can be ([below](#when-a-file-cannot-be-read)).
- **Follow**: while nothing has been saved on Quota Cache's page since the import, and the file is the record's, a newer revision saved by an older Quota Glance is copied again and recorded as `follow`. A follow that continues an `automatic` or `manual` import keeps that kind instead, as does a `matched` record written while nothing has been saved on the page since one, so the note keeps saying what may need entering again; the log names the follow either way. After a manual import, unless the two files were made equal again since, and after the imported settings file was put back over saves made on the page since CPA started, each copy also gives every row a revision newer than any page could hold, as the manual import does, so a page still open on one of those saves meets Quota Glance's value as a conflict. The first save on Quota Cache's page ends this, and the page asks before that save. A Quota Glance file whose revision is not newer, such as an old backup put back, is not followed; it shows as changed. Quota Glance numbers each save one past its file's revision, so once an old backup is put back, its next saves can reuse revisions this page already showed, for other values; a newer file that does not go on from the one copied, such as one Quota Glance saved after a backup was put back, or another file placed as the drop-in, is copied with every row given a newer revision, as after a manual import, so a page still open on the copy meets Quota Glance's value as a conflict. A drop-in is a copy: Quota Cache reads it in place of Quota Glance's real file, so it follows only when you copy the file again, and the page neither says it picks up Quota Glance's changes nor asks before the first save.
- **Manual**: **Import Quota Glance's settings** on the page, behind a confirmation that names what is saved here, which it replaces, and what Quota Glance's file holds now, which it brings. It replaces every saved value with the file's, gives every row a revision newer than any page could hold, past every revision the settings file had even when it was moved aside first, and writes a `manual` record. It is how a drop-in placed after a save, or after an import of another file, is imported, and how a store that was moved aside is filled again. It brings only what Quota Glance's file holds, and Quota Glance 0.8.0 no longer writes that file, so a value saved only on Quota Cache's page is not among them; the confirmation says when the file last changed, and the note after the import says to enter such values again. Pressing it twice is harmless. If CPA stops between writing the settings file and the record, while an earlier record names the same Quota Glance file, the next tick records the import from the files, as it does a follow that gave every row a newer revision: as `manual`, or as `automatic` when the earlier record is, since the files cannot tell the two apart ([import record](cache-format.md#import-record)).

Each import logs `quota-cache imported Quota Glance's settings` with its `kind` and its counts, never a value. A `matched` record logs nothing.

**After a `cache-path` move.** The settings file and the import record are operator data and must move with `cache-path`. If both are left behind, the new location looks like a first start and imports Quota Glance's file again, whose values date from before the move; the import note shows when they were last changed in Quota Glance, and says to enter again any value saved on the page before. If only the record moved, Quota Cache starts empty and offers the import.

### Import states

The published state's `settings.import` and the page's import note say where the import stands. The first that applies:

| State | When | The page |
| --- | --- | --- |
| `legacyUnreadable` | Quota Glance's file is there but cannot be read (not a regular file, over 1 MiB, or any rule). With neither a settings file nor a record, this also blocks editing (below) | A warning to fix it or move it aside |
| `settingsMissing` | An import record is there but the settings file is not | Starts empty and editable; offers **Import Quota Glance's settings again** while the file can be read. Saving before importing starts a new settings file, which holds none of the imported values, so the state becomes `notImported` and the import is still offered |
| (none) | No Quota Glance file, and no record or none that describes the settings file (below) | Nothing |
| `notImported` | Quota Glance's file can be read and no record describes it: none, one for another file, such as a drop-in placed later, or one that does not describe the settings file, because that holds none of what was imported: a copy from before the import put back, or a file a save here started after the imported one went missing, whatever was put back in between | Offers **Import Quota Glance's settings** |
| `imported` | The record describes the settings file, and its hash is Quota Glance's file's, or the record's file is gone | A note with what moved and when it was last changed in Quota Glance, for 30 days, dismissible. After a `matched` or `follow` import, which leave Quota Glance's values in the settings file with nothing saved here since, it says nothing needs entering again. A follow, or a `matched` record, that continues an `automatic` or manual import keeps that import's kind instead, and with it that import's line below. After the `automatic` import, which cannot tell a first start from a store refilled after its settings file and record were lost, it says that a value saved on this page before the import, if any, is not among them, to be entered again. After **Import Quota Glance's settings**, it says that a value saved only on this page is not among them, to be entered again. While follow mode lasts it also says the page picks up Quota Glance's changes; after a drop-in, that later saves in Quota Glance are not picked up |
| `changedSinceImport` | The file is the record's, but has changed since | Says an older Quota Glance still edits it, or, for a drop-in, that the copy changed, and offers **Import Quota Glance's settings again** |

While the import record is there but cannot be opened or read, such as one restored as another user, Quota Cache does not know what it says, so `settings.import` stays as Quota Cache last published it, or `null` when it has published none since it started, rather than reading as `notImported` and offering an import that would replace what was saved here.

`following` is true while follow mode lasts for Quota Glance's own file, and never after an import of a drop-in, which Quota Glance does not save to. `importable` is true while Quota Glance's file can be read. `counts` say what the last import brought. The status route's `editor.legacy` is the same block plus `file_counts`, what Quota Glance's file holds now, counted the same way, and `file_updated_at`, its newest change, each `null` while it cannot be read, and `file_updated_at` while it holds nothing. The import's confirmation names those beside what is saved here.

## When a file cannot be read

A settings or organizations file that fails any of its rules is never written over. Each tick (every 10 seconds) checks it again, so the remedy is to move it aside; the page picks that up within a few seconds, with no configure. A save or an import reads its file again first when it changed since the last tick, so neither writes over a good copy put back, a deleted file or one that fails its rules. An import record that fails its rules is the exception: the next record written replaces it, as **Matched** above describes.

- **The settings file.** Nothing saved applies, only configured values do, the page cannot save, and CPA's log says once per load: `quota-cache cannot read its saved API credit settings; only config values apply until the file is moved aside`. Put back a good copy of `snapshot.settings.json`, which keeps the values saved here, or move it aside. Once an import record exists, moving it aside starts Quota Cache empty, and **Import Quota Glance's settings again** brings back only what Quota Glance's file holds: a value saved only on this page is not in it, and has to be entered again. Saving a value first does not hide the import: the page goes on offering it, and importing replaces what was saved. A good copy put back after such a save counts as imported again if it holds the import, and goes on counting through later saves; a copy from before the import, or of a file started after the imported one went missing, counts as not imported, and the import is offered. Moving the settings file away then never imports Quota Glance's file automatically. Without a record, as when values were saved here before anything was imported, moving it aside is a first start. A Quota Glance `settings.json` that can be read is then imported automatically, even one the page offered and you did not import, and one that cannot be read blocks editing, as the next item says. To keep the values saved here, put back a good copy instead.
- **Quota Glance's `settings.json`, before the first import.** Nothing is imported, nothing saved applies, and the page cannot save, so a first save cannot shut the import out for good. CPA's log says once per load: `quota-cache cannot read Quota Glance's settings.json, so nothing was imported; fix or move it aside`. After an import, the same file is only a warning on the page.
- **The organizations file.** The configuration's list applies, and the page cannot change organizations. Values saved for an organization the configuration does not list are kept, shown on the API credit card as kept, and cannot be cleared meanwhile: they may belong to an organization in the file. Move `snapshot.organizations.json` aside: with organizations still in the configuration they move again, otherwise the list starts empty. Or fix it in place: a good copy put back applies at the next tick.
- **A file Quota Cache could not open or read**, such as one restored as another user, counts as unreadable too, but is read again at every tick: fixing its owner or permissions is enough, with no need to move it aside. The import record is read again at every tick and every save as well. While it cannot be opened or read, the saved values still apply, but the page cannot save or import settings, since a save could not tell whether the file it writes holds the import. The cards say so and name `snapshot.settings-import.json`, and the import note stays as it was.

## Rollback

Every value entered on the page survives a rollback unless step 2 imports Quota Glance's settings over it. An older Quota Cache knows only the organizations listed in its configuration, though, which the page never writes to (step 3). CPA's Plugin Store installs only the version this repository's catalog lists, so each downgrade below is done by hand, as [downgrading a plugin](#downgrading-a-plugin) describes. Roll back in this order, so that an editor always exists and nothing routes on figures nobody maintains:

1. **Reset Priority** first: turn `route-api-credits` off in Reset Priority's **Edit config** on CPA's Plugins page, wait until two consecutive requests leave the status's `router.counters.picks` unchanged, then downgrade. CPA calls the scheduler on every request, and a request that reaches Reset Priority while CPA replaces it fails. See [Updating or removing Reset Priority](../../reset-priority/REFERENCE.md#updating-or-removing-reset-priority).
2. **Quota Glance** to 0.7.2: first look at the import note on Quota Cache's page. If it reads **Changed in Quota Glance** or **Not imported**, Quota Glance's `settings.json` holds values Quota Cache does not, which the copy below replaces. To keep both, keep a copy of Quota Glance's `settings.json`. **Import Quota Glance's settings** brings Quota Glance's values onto the page instead, but replaces every value saved on the page since the last import, so use it only if those do not matter. With a drop-in the note describes the drop-in, so keep a copy of Quota Glance's own file either way. Then, while Quota Glance is disabled, or while CPA is stopped for the downgrade, copy Quota Cache's `snapshot.settings.json` byte for byte over Quota Glance's `settings.json` (the formats are the same), then downgrade. Quota Cache sees the two files equal and records the match: as `matched`, or, when nothing has been saved on the page since **Import Quota Glance's settings**, as that import, so its note stays. It then copies each save Quota Glance 0.7.2 makes as it is, for as long as nothing is saved on Quota Cache's page; after a save there, use **Import Quota Glance's settings again** to bring Quota Glance's edits over. With a drop-in, Quota Cache never reads Quota Glance's real file, so it never follows. Without the copy, Quota Glance 0.7.2 shows its values as they were at the import, plus its own later edits.
3. **Quota Cache** to 0.1.14 last. First make `claude-api-credits` in `config.yaml` match the page's **Organizations** list, each item with the `label` and `organization-id` the page shows, and with the configured values the **Claude API credits** card's editor shows for it as its `monthly-usd` and `renews`: a value marked from config, or the config value beside one entered here. The page takes those values from the organizations file since the move, while 0.1.14 and Quota Glance 0.7.2 take them only from the configuration, so an item without them leaves its organization with no monthly credit or refill date unless one was entered on the page. **Edit config** does not offer the list, and 0.2.0 ignores it, so editing it is safe. The list is as it was at the move unless you changed it since, or empty if every organization was added on the page: an organization added on the page is missing, a renamed one has its old label, one removed on the page is still there and comes back under 0.1.14, and an item or a whole list deleted since the move has to be written again, its `monthly-usd` and `renews` included. An organization the list lacks is not counted by 0.1.14: its traffic is still recorded for 40 days, so its history is there after a return to 0.2.0, but Quota Glance 0.7.2 shows its saved values as an orphan, and with no item at all 0.1.14 stops its meter. Then downgrade. 0.1.14 ignores the four new files (organizations, settings, import record and credit state) and never deletes them. Do not go further back with the list in place: 0.1.13 has no meter and marks every item that has `organization-id` as `unknown_field`, so nothing is counted, and 0.1.12 and older reject `claude-api-credits` altogether and stop polling, so Account Health and Reset Priority, where they read the cache, wait for data that never comes. To go back past 0.1.14, delete the list first. Quota Glance 0.8.0, if still installed, shows the last credit state as stale until it sees that no Quota Cache publishes it any more, then shows **no figures** with a note; moving `snapshot.credits.json` aside makes that immediate.

Back on 0.2.0, the organizations file is still there, so the configuration's list stays ignored, and with it every change made to `claude-api-credits` meanwhile: an organization added, removed or renamed, and a changed `monthly-usd` or `renews`. Each organization keeps the configured values it had at the move, which the page still shows as from config. Step 3 made the configuration's list match the page, so to take the configuration as it is now, delete `snapshot.organizations.json` after updating: the list moves again, each organization with its current `monthly-usd` and `renews` as its configured values, as [the move from the configuration](#organizations) describes. Values entered on the page are kept by organization, so they apply again to every organization still listed. Otherwise make the same changes again on the page.

### Downgrading a plugin

On CPA v8.0.22, the Plugin Store installs a plugin only at the version the catalog lists, and this repository's catalog lists only each plugin's newest release. To go back to an older `<version>` of a plugin `<id>` (`reset-priority`, `quota-glance` or `quota-cache`):

1. From the `<id>/v<version>` release on the repository's [GitHub Releases](https://github.com/NoorChasib/cpa-plugins/releases), download `<id>_<version>_linux_amd64.zip` and `checksums.txt`, and check the ZIP with `sha256sum --check --ignore-missing checksums.txt`. A published release is never replaced, so every older one stays there.
2. Stop CPA.
3. Copy `<id>.so` from the ZIP into `linux/amd64/` under CPA's plugin directory (`/CLIProxyAPI/plugins` in the official image) as `<id>-v<version>.so`, the name the Plugin Store gives a library it installs. Leave the newer library where it is.
4. In `config.yaml`, set `version` in the `store` block under `plugins.configs.<id>` to `<version>`, and change nothing else in that block. CPA loads the library whose version it names: without this edit CPA goes on loading the newer library, and deletes the one you placed.
5. Start CPA. Once it has loaded the older library, CPA deletes the newer one, and the Plugin Store offers **Update** again, which is how to return.

## Privacy

- The settings, organizations and credit state files hold labels, Organization IDs, amounts, dates and token counts: what Quota Glance's own file and document held. No key, auth ID, email or credential name is in any of them.
- The renewal card names each Claude credential by the address in its auth index, or the address or label CPA reports. Those names are held in memory only, never written to a file or a log, and returned only by the authenticated status route.
- Log lines name kinds, ids, field names and counts, never a value, amount, path, label, Organization ID or name. The lines are: `quota-cache imported Quota Glance's settings`, the two warnings above, `quota-cache settings changed` with `kind`, `ids` and `fields`, `quota-cache organizations changed` with `added`, `renamed` and `removed`, `quota-cache moved its Claude Console organizations to its page`, the configuration-ignored line, and `quota-cache could not publish its credit state` with a `reason`, at most every 10 minutes.
