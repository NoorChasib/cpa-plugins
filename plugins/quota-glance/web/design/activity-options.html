Quota Glance · which credential is taking the traffic

Four placements for the same fact, each drawn on the same Session card so only the activity treatment differs. The figures are shaped after the live pool: agency is carrying it right now, chasibnoor had a burst two hours ago, siphorchannel threw two failures, and two credentials have been idle all window.

The source is recent_requests on the roster this plugin already asks CPA for — 20 buckets of 10 minutes, so every mark below covers the last 3h20m and resolves to ten minutes. Blue is a success, red is a failure, and no provider request is involved.

Option 1

A dot beside the address

The smallest thing that answers the question. A filled, pulsing dot means this credential is taking requests in the current ten-minute bucket; a dimmed dot means it took some earlier in the window; a hollow ring means idle. No row height, no new column.

  • Says who, never when or how much; the hover title carries the last-request time and nothing is printed.
  • Survives the 390px reflow untouched: it rides in the address cell, which keeps its own line there.
  • Cheapest to build and to read — two dot states and a ring, no new colour anywhere.

  • Shows the shape of the traffic — a burst two hours ago reads differently from a steady drip, and only this option tells them apart.

  • No repetition — the fact is stated once per provider rather than once per window card.
  • Room for the detail: count, last request and failures, without crowding a quota row.
  • Two places to look — the credential you are reading in the Weekly card is a separate row up here.
  • Adds a card to the top of every provider section, which pushes quota, the page's actual subject, further down.

Worth combining. 1 + 4 puts a live marker on every row and the timeline once, with no per-row height cost. 1 + 3 is the cheapest pair that answers both who now and what share. 2a stands alone best: one mark, in one place, nothing else added.

One implementation note. The document is rebuilt only when quota-cache writes a new snapshot — every 15 minutes by default — so any of these would refresh on that cadence until the plugin also republishes on a short timer. The roster call is in-process and free, so that timer costs nothing and still makes no provider request.
